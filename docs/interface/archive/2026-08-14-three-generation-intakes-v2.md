# Три отдельные формы создания видео · v2

Дата: 2026-08-14  
Маршрут: `#/workspace/generation`  
Статус: implementation branch / review required

## Проблема

Текущий экран начинался с выбора одной из трёх бизнес-стратегий, но затем протаскивал пользователя через одну универсальную форму. В результате оператор видел поля, которые относились к другой задаче: выбор десяти исходных роликов, технические роли изображений, общие настройки модели и полный сценарный бриф даже тогда, когда хотел только повторить один ролик или заменить героя аватаром.

Это нарушало главный принцип интерфейса ContentEngine: **одно действие — один понятный рабочий стол**.

## Новая структура

### 1. Скопировать ролик

Пользователь видит только:

1. ссылку на один ролик;
2. фото своего товара;
3. необязательное описание отличий.

Пустое описание означает: повторять механику референса без дополнительных творческих изменений.

Внутренний маршрут:

```text
ссылка
→ регистрация точного источника
→ прикрепление законного MP4
→ разбор кадров, движения, света, темпа и звука
→ автоматическое извлечение референса исходного товара
→ Product Swap
→ ручной QA
```

Фото исходного товара из ролика не должно запрашиваться у пользователя. Это внутренний технический артефакт, который система получает при анализе видео.

Сервер дополнительно проверяет выбранные фото товара непосредственно в момент сохранения intake:

- все изображения принадлежат текущим организации и проекту;
- имеют статус `ready`;
- являются JPEG, PNG или WebP;
- классифицированы как `product_photo` или `packshot`;
- имеют подтверждённые права;
- относятся к source-артефактам, а не к сгенерированным output;
- принадлежат одному активному товару.

Важно: обещание сформулировано честно. Система стремится сохранить действия, ракурсы, темп, свет, композицию и монтаж максимально близко, но не обещает математическую пиксель-в-пиксель идентичность генеративного результата.

### 2. Сделать с аватаром

Пользователь видит только:

1. пожелания к аватару;
2. ссылку на ролик;
3. необязательный комментарий.

Внутренний маршрут:

```text
пожелания к аватару + ссылка
→ регистрация источника
→ прикрепление законного MP4
→ разбор движений, речи, темпа и ракурсов
→ подготовка изображения аватара
→ Character Performance
→ ручной QA
```

Пользователь не обязан заранее готовить технический character reference, выбирать provider recipe или разбираться, какой референс требуется модели. Если такой референс нужен, система создаёт его как отдельный контролируемый внутренний этап.

Этот маршрут **не маскируется под существующий `viral_avatar_ugc`**. Старый Product UGC-контракт требует другого набора артефактов и согласий. Поэтому новый операторский intake фиксирует рецепт `character_performance`, а provider/model authority появится только после отдельного server-side preparation worker и полного preflight.

### 3. Создать видео по стратегии

Это единственный маршрут, где остаётся полный конструктор:

```text
товар
→ площадка и назначение
→ замысел / сценарий
→ исходники
→ рекомендации по модели
→ длительность, формат, звук
→ кампания и бюджет
→ preflight
→ явное подтверждение оплаты
→ генерация
→ QA
```

Он продолжает использовать существующую server strategy `viral_rebuild` и действующий generation-spec flow.

## Безопасность и деньги

Компактные формы являются этапом подготовки. Они:

- не вызывают провайдера;
- не запускают платную генерацию;
- не резервируют бюджет;
- не принимают цену от браузера;
- не выбирают provider/model как authority;
- сохраняют ввод в append-only server intake;
- требуют законный MP4 для реального разбора кадров и аудио;
- сохраняют обязательный человеческий QA.

Полный стратегический маршрут продолжает использовать действующие generation spec, provider preflight, campaign budget, idempotency, reconciliation и review gates.

## Точный источник и MP4 — разные факты

Ссылка YouTube регистрирует идентичность источника и остаётся в статусе `awaiting_media`. Она никогда не считается просмотренным видео.

Факт реальных видеобайтов хранится отдельно в append-only привязке:

```text
content_factory.research_exact_youtube_media_attachments
```

Новый intake читает именно эту привязку. Поэтому состояние различается честно:

- `awaiting_source_media` — ссылка зарегистрирована, MP4 ещё не прикреплён;
- `source_media_ready_for_preparation` — есть точный attachment с SHA-256 и подтверждением прав/соответствия источнику.

## Серверный контракт

Добавлена append-only сущность:

```text
content_factory.generation_intakes_v2
```

И RPC:

```text
public.creator_save_generation_intake_v2(jsonb)
```

RPC принимает только два компактных маршрута:

- `copy_video` → preparation recipe `product_swap`;
- `avatar_video` → preparation recipe `character_performance`.

`strategy_video` не дублируется в новой таблице и продолжает использовать текущий полный generation-spec flow.

Сохраняются:

- проект и организация;
- точный зарегистрированный источник;
- точная attachment-привязка MP4, если она уже существует;
- SHA-256 прикреплённого MP4;
- операторский маршрут;
- preparation recipe;
- пожелания к аватару;
- необязательное описание;
- выбранные фото и один точный product ID только для копирования;
- input hash;
- idempotency key;
- следующий безопасный шаг.

Записи не редактируются и не удаляются. Изменение формы создаёт новый immutable intake с новым input hash.

## Совместимость и границы authority

| Новый операторский маршрут | Preparation recipe | Действующая server strategy authority |
|---|---|---|
| `copy_video` | `product_swap` | `viral_product_swap` — подключается позднее после полной подготовки артефактов |
| `avatar_video` | `character_performance` | отсутствует; нельзя подменять старым Product UGC |
| `strategy_video` | `generation_spec` | `viral_rebuild` |

Старый strategy catalog остаётся в DOM как совместимый server-owned слой, но его перегруженная карточная стена скрыта от оператора. Новый интерфейс вызывает существующий authority control только для полного стратегического маршрута. Компактные формы не кликают старые paid-selection controls.

## Доступность

- три стратегии представлены обычными кнопками с `aria-pressed`;
- видимый focus ring;
- статусы объявляются через `aria-live`;
- compact/full состояние не клонирует нативные controls;
- карточки товара перемещаются, а не копируются;
- Enter в компактной форме сохраняет подготовку, но не вызывает legacy submit;
- поддерживается `prefers-reduced-motion`;
- отдельная адаптация для ширины 980 и 680 px.

## Что сознательно не обещано

Ссылка YouTube — это идентификатор источника, а не видеобайты. До прикрепления законного MP4 система не заявляет, что ИИ посмотрел ролик, не создаёт analysis evidence и не запускает платную модель.

Автоматический анализ MP4, извлечение изображения исходного товара, генерация avatar reference и фактические paid provider adapters являются следующими внутренними preparation/execution workers. Операторская форма уже не просит эти артефакты у человека, но paid launch должен оставаться заблокированным, пока они реально не созданы, не связаны с generation spec и не прошли проверку.
