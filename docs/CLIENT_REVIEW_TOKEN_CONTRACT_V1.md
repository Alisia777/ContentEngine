# Контракт клиентского токена: витрина (ступень 1) ↔ ввод (ступень 2)

Дата: 2026-09-03. Статус: зафиксирован ДО написания схемы витрины —
edge клиентского ввода строится поверх этого же токена, и менять контракт
после выкладки витрины значит переписывать оба контура.

## Принципы

1. **Один токен на клиента-кампанию.** Токен-ссылка витрины — единственный
   клиентский вход обеих ступеней: согласование роликов (ступень 1) и
   вкладка «Материалы и бриф» (ступень 2) живут на одной странице по
   одному токену. Второго токена/ссылки не заводим.
2. **Токен = вся авторизация.** Клиент не логинится; auth-учётка ему не
   создаётся. Все клиентские действия идут через edge-функцию с
   service_role и системные RPC — аноним напрямую в базу не ходит
   (после 202609030007 default privileges ничего и не раздают).
3. **Анти-энумерация по образцу creator-recovery**: ответы на неверный/
   отозванный/просроченный токен неотличимы; квоты и rate-limit на IP+токен.

## Обязательные поля строки токена (таблица витрины)

| Поле | Зачем вводу (ступень 2) |
| --- | --- |
| `token_hash` (sha256, сам токен ≥128 бит, в базе только хеш) | поиск строки |
| `organization_id` | все системные RPC требуют организацию |
| `campaign_id` | клиент = кампания; ролики и брифы скоупятся ей |
| `project_id` | загрузки и товары живут в проекте |
| `expires_at`, `revoked_at` | TTL и отзыв — общие для обеих ступеней |
| `intake_enabled boolean default false` | вкладка «Материалы и бриф» включается оператором отдельно от витрины |
| `intake_owner_profile_id` | под чьим профилем регистрируются клиентские файлы (media_objects требует путь org/<profile>/ и членство) |
| `view_count`, `decision_count`, `upload_count`, `brief_count` | квоты |

## Контракт ответа «резолв токена» (внутренний, edge → страница)

Резолв обязан отдавать одним ответом: `ok`, `campaign` (id, название),
`review` (ролики на согласование — ступень 1), `intake` (enabled,
лимиты, товары кампании для привязки брифа — ступень 2). Страница одна,
вкладки включаются флагами; неизвестные ключи страница игнорирует.

## Квоты по умолчанию (правится в строке токена)

- Витрина: TTL 14 дней, 500 просмотров, 100 решений.
- Ввод: 20 файлов/сутки, 5 брифов/сутки, 50 МБ/файл (кап bucket'а).

## Правила ступени 2 поверх токена

- Файлы клиента идут по **подписанным upload-URL** в приватный бакет —
  НИКОГДА через тело edge-функции (боевой урок: Memory limit exceeded на
  потоковой приёмке MP4, 21–23.08).
- Каждая загрузка — с чекбоксом аттестации прав (`rights_confirmed`),
  значение пишется в metadata.
- Принимаются фото товара и СВОИ видео товара; чужие вирусные ролики для
  «Копии» через клиентский ввод не принимаются вообще (ст. 1301 ГК).
- Клиентские материалы НИКОГДА не попадают в генерацию автоматически —
  только после «Принять в работу» оператором в SPA.
- Поля брифа — только с префиксом `brief_` (санитайзер Desktop v4 режет
  name="name"/"title" — задокументированная DOM-clobbering-мина).

## Явные гранты

Каждый объект контуров витрины/ввода несёт явные гранты (default
privileges после 202609030007 пусты): таблицы — только service_role,
RPC — только service_role; authenticated получает лишь операторские
creator_*-обёртки с membership-проверкой.
