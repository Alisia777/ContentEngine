# Harly 10× Localization & Competitor Intelligence v1

## Решение встречи

Следующий приоритет ContentEngine — не ещё один изолированный генератор, а
управляемый цикл:

`конкурентные аккаунты → кандидаты → решение → 10 роликов → QA → публикация → зрелые метрики → обучение`.

В интерфейсе это остаётся частью двух существующих рабочих пространств:

- **Разбор товара** — аккаунты, кандидаты и решение `Повторить механику / Сделать новое / Не использовать`;
- **Создание** — `Локализовать своё`, пакет из 10, стоимость, волны и QA.

Новый второй Dock, отдельный микрокабинет и россыпь карточек запрещены.

## Четыре решения для найденного видео

### 1. Локализовать своё

Допустимо только для owned/licensed source с подтверждёнными правами и source
QA. Видеоряд можно сохранить, речь/субтитры — перевести.

### 2. Повторить механику

Для публичного ролика конкурента переносится только allowlisted структура:

- тип хука;
- темп;
- тип доказательства;
- CTA;
- диапазон количества кадров;
- момент появления товара.

Не переносится raw caption, чужой товар, упаковка, лицо, музыка, слоган и точная
последовательность кадров.

### 3. Сделать новое

Если прав или полезной структуры нет, мини‑ИИ формирует bounded hypothesis для
этой же `learning_category_key`. Winner другой категории не наследуется.

### 4. Не использовать

Недостаточно данных, не подтверждён public access, дубликат, права неясны или
структурная выжимка пуста.

## API-источники

| Площадка | Первый безопасный путь | Что важно |
|---|---|---|
| YouTube | официальный Data API | публичные каналы/видео, quota и Terms |
| TikTok, свой/авторизованный аккаунт | Display API | не источник произвольных конкурентов |
| TikTok, исследовательский контур | Research API | отдельный approval; не коммерческий production adapter |
| TikTok/Instagram, публичные конкуренты | лицензированный public-data vendor | server-side key, spend cap, receipts, ToS review |

Первый коммерческий adapter остаётся provider-neutral. В browser не попадают
ключи провайдера, raw URL, captions и private/behind-login content.

### Ориентир стоимости ingestion

Для первичного пилота достаточно порядка 10–20 аккаунтов и последних/лучших
роликов. Провайдер выбирается не по красивому лендингу, а по тесту:

- полнота полей;
- воспроизводимость;
- дедупликация;
- latency;
- rate-limit;
- цена 1 000 валидных записей;
- договорные права на коммерческое использование публичных данных.

## Пилот Harly: ровно 10 роликов

Первая дешёвая матрица:

- 5 owned/licensed исходников Harly;
- 1 целевой язык;
- 2 режима на каждый исходник:
  - субтитры;
  - дубляж без lip-sync;
- итого 10 уникальных assignments.

Волна 1 — два результата: один subtitles и один dub. После human QA продолжаются
оставшиеся восемь. При общем техническом дефекте batch останавливается, а не
сжигает весь бюджет.

## Три уровня локализации

### A. Субтитры — основной дешёвый режим

`audio → transcript → translation → SRT/VTT → burn-in/export`.

Если в оригинале есть встроенные надписи, assignment получает обязательную
ручную правку: автоматические субтитры не должны лечь поверх старого текста.

### B. Дубляж без lip-sync — основной голосовой режим

Сохраняем видеоряд, переводим речь, стараемся сохранить фон и тембр. Этот режим
обычно кратно дешевле полной повторной генерации и не обещает совпадение губ.

### C. Lip-sync — premium

Запускается только после отдельного cost preview и проверки первых дешёвых
версий. Нельзя делать его default для всех десяти роликов.

## Rate-card snapshot для dry-run

`2026-08-01.public-provider-rate-card.v1`, micro-USD:

- internal captions budget envelope: `$0.05 / minute`;
- ElevenLabs dubbing without watermark: `$0.50 / minute`;
- HeyGen audio-only translation: `$0.0333 / second`;
- HeyGen speed lip-sync: `$0.0333 / second`;
- HeyGen precision lip-sync: `$0.0667 / second`;
- Seedance full-generation baseline: `$0.29 / second`.

Последняя строка — сравнительный baseline текущего ContentEngine, а не обещание
провайдера локализации. Перед реальным списанием rate card должен сохраняться в
server receipt. Расчёт линейный; налоги, минимумы биллинга, хранение и повторные
прогоны проверяются отдельно перед production запуском.

### Пример: 5 исходников по 8 секунд, subtitles + dubbing

- 5 subtitle outputs: около `$0.0333`;
- 5 dubbing outputs: около `$0.3333`;
- всего dry-run: около `$0.3667`;
- 10 полных Seedance generation jobs: `$23.20`;
- расчётная экономия: больше `98%` до учёта хранения, QA и публикации.

Это не означает, что локализация заменяет генерацию вообще. Она дешёво умножает
**уже принадлежащие бренду хорошие исходники**; новые сюжеты всё равно проходят
обычный experiment loop.

## Как обучается мини‑ИИ

Публичная метрика конкурента используется только для discovery. Просмотры,
лайки и скорость роста не являются продажами и не объявляют winner.

В обучение результата допускается только цепочка:

`наш output → независимый QA → опубликованная ссылка → зрелое окно метрик → orders/sales/conversion/CPO → matched comparison`.

Promotion и rollback требуют server-backed import, immutable assignment,
policy hash и audit. Browser draft не является authority.

## МБТ после Harly

МБТ — второй пилот ingestion, но не первая платная генерация:

1. выбрать точную категорию (`air_fryer`, `hair_dryer`, `robot_vacuum` и т.п.);
2. 10–20 конкурентных аккаунтов;
3. recent + top cohort;
4. human review top candidates;
5. три experiment families: control + две новые гипотезы;
6. не переносить Harly winner в МБТ.

## Что реализовано в v1 core

- строгий public-observation schema без raw URL/caption/prompt;
- discovery ranking для human review;
- rights-aware action routing;
- provider-capability boundary;
- deterministic batch planner на 10 локализаций;
- cost preview и full-generation baseline;
- волна 2 только после QA первых двух;
- offline CLI, который не вызывает API и не запускает оплату.

Следующий production этап: durable server tables, provider adapter, media
pipeline, captions/dub receipts, UI внутри существующих рабочих пространств и
outcome binding к issue #119.
