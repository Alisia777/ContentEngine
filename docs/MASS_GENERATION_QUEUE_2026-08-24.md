# Конвейер массовой генерации: 50–100 роликов в день

Дата: 24.08.2026. Заказ: Виктор — «парсить ролики, чуть их корректировать, массово,
по 50–100 в день как минимум; нужно закрыть блок с созданием контента».
Владелец: «мы к массовости не готовы — идея: очередь создания».

## Что уже есть (фундамент конвейера)

- Маршрут «Копия» (viral_product_swap) — ровно «парсить и чуть корректировать»:
  чужой MP4 + фото нашего товара → ролик с заменённым товаром. Пройден платно
  (Kling O3 Standard, $1.95) до «Опубликовано».
- «Материалы» принимают до 20 файлов за одну загрузку; exact-10 в «Сценарии
  с нуля» уже умеет пачку из 10 работ — фан-аут батча в базе существует
  (generation_batches → generation_jobs, ordinal).
- Воркер опроса провайдера, денежные резервы с лимитами (день/месяц/запрос),
  идемпотентность, «Очередь запусков» в форме.
- Приёмка: очередь «Ролики на проверке» (плеер + принять/отвергнуть),
  контур размещения, воронка в «Результатах».

## Экономика (проверенные ставки fal, уточнять перед стартом)

| Движок | Ставка | 50/день | 100/день |
| --- | --- | --- | --- |
| Pika v2 swap (8 c) | ≈ $0.47/ролик | ≈ $23.5 | ≈ $47 |
| Kling O3 Standard | ≈ $1.95/ролик | ≈ $97.5 | ≈ $195 |

Время: 5–15 мин/ролик — не блокер при параллельности 3–4 задачи:
100 × 8 мин ÷ 3 ≈ 4,5 часа конвейерного времени в сутки.

## Узкие места к 50–100/день

1. **Форма — один запуск за раз.** Нужен фан-аут «Копии»: N исходников × 1
   товар = N нарядов одним подтверждением цены.
2. **Дневной лимит политики спенда** сейчас $25/день — под 50 Pika надо ~$25–50,
   под Kling — $100–200. Поднимается владельцем в «Команда → Расходы» осознанно.
3. **Параллельность провайдера.** fal держит очередь сам; наш воркер опрашивает
   последовательно. Нужен параллелизм 3–4 активных наряда + пауза между
   постановками (защита от rate limit).
4. **Человеческая приёмка.** 50–100 роликов ≈ 1.5–3 часа просмотра. Инбокс
   проверки уже конвейерный; дальше — авто-предфильтр (M3).
5. **Исходники.** 50–100 чужих роликов/день надо добывать. Подтверждения
   transformative use в форме есть; сам парсинг — отдельный контур (в реестре
   исследований YouTube-инжест уже живёт — расширить на выдачу кандидатов
   конвейеру).

## Фазы

- **M0 «Живая очередь по одному» — СДЕЛАНО 24.08 (stamp .61).** Определение
  владельца: «сделала 1-й ролик, потом ставлю задачу 2-й — и оно подвешивается
  в очередь». Раньше замок платного контекста держал ВСЮ форму до конца
  генерации (5–15 мин): фаза status попадала в список блокирующих. Теперь
  замок держит только денежное решение в полёте (human_confirmed/start_once,
  секунды), а с появлением generation_job_id форма свободна — следующий ролик
  готовится и запускается, пока предыдущие крутятся; все статусы в «Очереди
  запусков», клиентский опрос идёт по всем активным нарядам параллельно.

- **M1 «Очередь создания» (следующий слайс).** На «Копии» появляется режим
  «Пачка»: выбрать товар + фото + до 20 исходников → один батч из N нарядов с
  одним подтверждением цены; последовательные платные старты со статусами в
  «Очереди запусков»; готовые падают в «Ролики на проверке». Отказ одного
  наряда не роняет батч.

### Карта внедрения M1 (разведано 24.08, вечер)

Пачка УЖЕ работает для «Сценария с нуля» (ровно 10): подготовка N ТЗ пачками
по 3 (`prepareGenerationStrategySpecs`), поимённое одобрение, «Проверить N
ассетов и цен бесплатно» с общей суммой, последовательные платные старты с
resume/сверкой (`planGenerationStrategyQueueSequentialStarts`). Модули очереди
и runtime количество-агностичны; edge не проверяет число (маркер
`GENERATION_STRATEGY_EXACT_10_*` — чисто клиентский). «10» зашито в двух
местах:

1. `generation-strategy-source-picker.js` —
   `GENERATION_STRATEGY_SOURCE_REQUIREMENTS` (`viral_product_swap: 1`,
   `viral_rebuild: 10`): нужен динамический `requested_count` (1–20 для
   «Копии») в состоянии пикера.
2. `app.js`, ветка exact-ten sync (~30860+): подписи «10», `=== 10`,
   маркер подтверждения — заменить на переменную `requiredCount`.

Плюс UI: пикер исходников сейчас монтируется только в маршруте «Сценария
с нуля» — «Копии» нужен выбор пачки (переключатель 1/5/10/20 + мультивыбор
привязанных MP4). Проверка — зондом `browser_copy_flow_probe` в режиме пачки.
- **M2 Темп и бюджет.** Параллелизм 3–4, приоритеты, ретрай с новым резервом,
  дневной кап конвейера отдельным полем политики, отчёт «сколько сегодня
  сделали/потратили» в воронке.
- **M3 Авто-предфильтр приёмки.** Дешёвые проверки до человека: длительность,
  битый файл, чёрный первый кадр, тишина там, где ждали звук; сомнительное —
  в начало очереди проверки с пометкой.
- **Параллельно (уже в плане):** реестр аккаунтов → фаза 1 ручной очереди
  размещения → Telegram-бот/YouTube OAuth (Виктор: «акки и автопостинг решим»).

## Риски, названные вслух

- Массовая «Копия» = массовое использование чужих механик: подтверждение
  трансформативности остаётся на человеке, пачка не отменяет галочки.
- Провайдер может резать качество/лимиты на объёме — начинать M1 с 20/день и
  поднимать, глядя на брак в «Проверке».
- Деньги списываются за брак тоже: авто-предфильтр (M3) окупается сразу.
