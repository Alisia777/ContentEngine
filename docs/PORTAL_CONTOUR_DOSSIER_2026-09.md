# Досье: контур public.portal_* (второй продукт в базе)

Дата: 2026-09-03. Прод iyckwryrucqrxwlowxow. Статус: контур ЖИВОЙ,
обнесён забором по членству (миграция 202609030006), не удалён.

## Что это

В той же базе, что и Контент-Завод, живёт второй контур — портал задач
и цен (17 таблиц `public.portal_*`): задачи (484 строки, последняя
03.08.2026), комментарии (по 31.07), WB-снапшоты данных (4 190 строк,
последняя 16.08 — самая свежая активность), ценовой верстак, номенклатура,
статусы Маши (`view_portal_masha_status_current`), дизайн-workspace.
Код Контент-Завода к этим таблицам НЕ обращается (проверено grep по
web/app) — сцепки нет.

## Что было не так

До 03.09 одиннадцать таблиц держали политики `qual=true` для роли
`authenticated` — то есть ЛЮБОЙ вошедший пользователь (включая будущие
клиентские учётки Контент-Завода) имел полный CRUD к задачам, ценам и
номенклатуре. Две таблицы (`portal_data_snapshots`,
`portal_task_attachments`) открыты ещё и для `anon`.

## Что сделано (203.09, недеструктивно)

- `public.portal_members` + сид всеми 40 живыми (неанонимными) учётками —
  ни один пользователь портала доступ не потерял.
- На 11 таблицах политики `qual=true` заменены на членский забор
  (EXISTS по portal_members). Клиентская учётка вне таблицы получает 0 строк.
- Гигиена public: default privileges для новых объектов больше не раздают
  права anon/authenticated; search_path закреплён; duet-RPC закрыты от anon
  (миграция 202609030007).

## Что НЕ сделано и ждёт ответов команды (вопросы Сергею → команде qeep.life)

1. **Кто пишет WB-снапшоты** (`portal_data_snapshots`, свежие до 16.08)
   и каким ключом — anon или логином? Anon-политики на снапшотах и
   вложениях СОХРАНЕНЫ, чтобы не сломать писателя. После пересадки
   писателя на служебный логин/сервисный ключ — снимаем anon-политики.
2. **Бакет `portal-task-files`** (public, anon-писуемый, 41 файл): как
   грузятся вложения? После ответа — private + signed URLs.
3. **Статус Маши**: читает ли кто-то `view_portal_masha_status_current`
   БЕЗ входа (публичная страничка)? Единственный оставшийся ERROR
   advisors — security definer view с anon-доступом. Если публичного
   читателя нет — вешаем security_invoker и снимаем anon (заготовка есть).
4. **Владелец контура**: кому портал принадлежит и планируется ли переезд
   в отдельный Supabase-проект (рекомендация аудита — месяц 2; сцепки с
   Контент-Заводом нет, переезд дешёвый).

## Правило для новых объектов
