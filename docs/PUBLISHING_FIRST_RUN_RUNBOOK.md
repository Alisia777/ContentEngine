# Первый боевой прогон публикации: runbook

Дата: 2026-09-03. Цель: провести ОДИН placement через очередь до
`published` с final_url — впервые за историю продукта. Первый прогон —
ORGANIC (собственный канал, без рекламы) — ERID не нужен; рекламный с
ERID — вторым прогоном по docs/ORD_ERID_RUNBOOK.md.

## Роли

- **Оператор** — заводит размещение, постит руками, вписывает final_url.
- **Второй человек (Алисия)** — подтверждает публикацию (форма
  подтверждения с compliance-чекбоксом; правило независимости).
- **Сергей** — заранее: аккаунты в «Команда → Аккаунты» и выдача
  оператору.

## Критические предупреждения

1. **Старые 9 placements (июль–13.08) для очереди НЕПРИГОДНЫ** — у них
   нет managed_account_id, очередь ответит
   `publishing_enqueue_account_missing`. Прогон только через СВЕЖИЙ
   placement из «Одобрить и разместить».
2. **Трекинг-ссылка обязательна до формы final_url** — без готовой
   трекинг-ссылки форма подтверждения на карточке скрыта.
3. Подтверждает не тот, кто постил.

## Предполётный чек (read-only, выполняет Клод по запросу)

- cron `contentengine-publishing-dispatch-v1` активен;
- выбранный managed_account: status active, режим assisted;
- у ролика metadata.kind='generated_video' и status='ready';
- у оператора-исполнителя есть выдача аккаунта.

## Шаги

1. **Сергей**: «Команда → Аккаунты» → завести аккаунт площадки (TG или
   VK), выдать оператору.
2. **Оператор**: карточка готового ролика → «Одобрить и разместить» →
   выбрать аккаунт, режим ORGANIC (или ERID для рекламы) → создать
   размещение. Появится свежий placement с привязанным аккаунтом.
3. **Оператор**: на карточке размещения — «Запланировать публикацию»
   (кнопка активна для owner/admin до боевой приёмки; оператору её
   включит pub-10 после зелёного прогона) → наряд встаёт в очередь.
4. Диспетчер (каждую минуту) переводит наряд в `manual_required` и шлёт
   уведомление с готовой подписью.
5. **Оператор**: публикует пост руками с подписью из уведомления,
   копирует ссылку на пост.
6. **Оператор**: настраивает трекинг-ссылку (если ещё нет) — без неё
   форма подтверждения не появится.
7. **Алисия**: на карточке размещения — форма «Ссылка на опубликованный
   пост»: вставить final_url, отметить compliance-чекбокс, подтвердить.
8. **Автоматика** (миграция 202609030017): подтверждение закрывает наряд
   очереди — status `published`, provider_post_id `manual:<placement>`,
   событие в publishing_job_events. Вечных manual_required-хвостов нет.

## Готово, когда

- placements: строка с final_url и published-подтверждением;
- publishing_jobs: наряд `published` с событием 'published';
- уведомление «Публикация вышла» пришло постановщику;
- дублей уведомлений нет.

После зелёного прогона: снять гейт кнопки (pub-10, правка app.js +
выкладка) и показать статус наряда на карточке размещения.
