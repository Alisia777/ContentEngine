## 0. Что подтвердилось

Чтобы отчёт был честным в обе стороны — эти заявления проверены и верны:

- **Платный контур не ослаблен.** Единственный authority — `creator-generate`;
  прямых обращений к провайдерам из браузера нет; форма с платной
  авторитетностью в приложении ровно одна; серверные гейты платного старта в
  submit-функциях не тронуты; проверка готовности исходника не ослаблена, а
  усилена; путь инвалидации расширен новым платным полем движка.
- **CSS-слой дисциплинирован.** Подключён после канонического shell; ни одного
  правила с голым тегом в корне селектора; `!important` — 18 деклараций;
  структурно валиден; синтаксических ошибок и конфликтующих дублей нет; не течёт
  в неаутентифицированный портал (класс `contentengine-desktop-v4` ставится и
  снимается вместе с v4-шеллом); там, где слой задаёт `display` элементу, который
  JS переключает через `.hidden`, стоит guard.
- **Безусловные цвета — не дефект.** В проекте существует ровно одна тема:
  `theme-bootstrap.js` содержит `const allowed = new Set(["obsidian"])`. Светлой
  темы нет, поэтому отсутствие `prefers-color-scheme` контраст не ломает.
- **Локальный шаблон текста** вставляется только по явному нажатию и только в
  пустое поле; текстуально отделён от рекомендации ИИ-центра.
- **Правка человека доходит до модели** — и для всех трёх стратегий, не только
  для «Копии».
- **Профиль модели на маршруте стратегии отключается штатно**, по замыслу. Это
  не поломка (см. §2.1 о том, что из этого следует для заявления).
- SDK Supabase уехал с CDN на same-origin `vendor/`, и это проверяется сборкой.

## 1. Ломает

### 1.1 «Создание» — единственная стратегия без маршрута, которой разрешён платный старт

`app.js:29863` глушит всё, кроме `viral_product_swap` и `viral_rebuild`:

```js
if (strategyId !== "viral_rebuild") {
  return syncUnsupportedGenerationStrategyFormReadiness(form, strategyId, sourceProjection);
}
```

У «Аватара» рядом стоит явный feature-gate (`app.js:31277-31283`), у «Создания»
— нет. Путь до денег живой: `app.js:31259-31272` → `submitGenerationStrategyExactTen`
→ `startGenerationStrategyQueueSequentially` → `requestApi.startGenerationStrategy`.

Что увидит оператор: карточку «МОДУЛЬ 03 · runway · product_ad» без плашки
недоступности, честную бесплатную лестницу («Подготовить 10 роликов бесплатно» →
«Одобрить N ТЗ бесплатно» → «Проверить 10 ассетов и цен бесплатно»), затем точную
сумму, чекбокс «Подтверждаю 10 отдельных платных запусков» и разблокированную
кнопку «Запустить 10 роликов последовательно · $XX.XX».

**Денег провайдер не возьмёт.** 404 входит в `DEFINITIVE_CREATE_HTTP_STATUSES`,
наряд помечается `provider_request_rejected`, и без `provider_task_id` база
считает отказ доказанно неоплаченным ([202608190005:108-114](../supabase/migrations/202608190005_generation_strategy_daily_quota_paid_failure_v1.sql:108))
— резерв освобождается. Ущерб в другом: очередь замирает в платном состоянии
(«Ожидаем фиксацию» / «Нужна сверка неопределённого старта»), и весь цикл
подготовки потрачен впустую.

Визуальный слой этого не закрыл: `git diff -- web/app/app.js | grep viral_rebuild`
пуст. Слой добавил стратегии только собственный акцент
(`--ce-ref-strategy-accent: var(--ce-ref-cyan)`) — ни `display:none`, ни
`pointer-events`.

### 1.2 Состояние `ready` врёт

```js
setStrategyModuleState(form, missing.length || incompleteSources ? "blocked" : "ready");
```
— `workspace-os-v4-generation-guided.js`, около строки 1836.

`ready` решается исключительно полнотой ассетов. Признака «у стратегии нет
исполнимого маршрута» в модуле нет вовсе. Хуже: список обязательных ролей
фильтруется по карте контролов, а карта знает только `source_video`,
`avatar_image`, `original_product_image` — поэтому для «Создания» роли
`product_image` (1–10) и `style_image` (0–4) **не проверяются никогда**.

Оператор видит зелёное «Исходный MP4 выбран и проверен сервером» там, где сервер
откажет.

### 1.3 «Аватар» не изменился ни на байт

`git diff` по `prepareAvatar` / `character_performance` / `launch_enabled` —
пусто. Сверка тел функций между `git show HEAD:` и рабочей копией дала совпадение.

Остались все три дефекта, описанные в архитектурном разборе:
`strategy_id: "character_performance"` (идентификатора нет в реестре стратегий
базы), `product_media_ids: []` при обязательной роли `product_image`, финал в
локальном `persistHandoff` с зелёным статусом вместо обращения к серверу.

Визуальный слой добавил модулю шапку вида «МОДУЛЬ 01 · runway · product_ugc» —
то есть **усилил ложную идентичность**: оператор читает несуществующий рецепт
провайдера как подтверждение рабочего маршрута.

### 1.4 «ИИ предлагает — человек решает» не переживает перерисовку

Четыре независимые дыры в провенансе:

1. **Метка «операторский текст» живёт только в DOM.** `markBriefAsOperatorOwned`
   чистит датасеты поля и `form.dataset.researchRecommendationAppliedFields`, но
   не трогает состояние модуля рекомендаций в `sessionStorage`. На следующем
   рендере `restoreResearchRecommendationPresetLineage` заново штампует
   `researchRecommendationApplied` на то же поле — и текст человека получает
   ярлык «Из ИИ-центра».
2. **Восстановление локального черновика ставит `brief` без провенанса вообще**
   (`app.js:2586`, `:2591`). Любой ранее сохранённый текст, включая пришедший из
   ИИ-центра, после восстановления считается операторским.
3. **Два автозаполнения замысла без клика человека:**
   `applyGenerationAiResearchWorkingDraft` (`app.js:2712`, запускается
   автоматически при загрузке) и `applyIntakeHandoffBrief`
   (`guided.js:4970`, на монтировании). Заявление «не вставляется автоматически»
   верно только для локального шаблона.
4. **`ai_center_unverified` — тупик.** Выйти из него можно только кнопкой
   вставки шаблона, а она работает исключительно при пустом поле. Оператор не
   может объявить свой текст своим, не стерев его целиком.

Отдельно: `applyIntakeHandoffBrief` диспатчит `input` после программной записи,
и обработчик рекомендаций помечает поле как отредактированное человеком —
автоподстановка сама себя записывает в «человеческие правки».

## 2. Расхождения с отчётом

### 2.1 «Профиль под каждую модель» относится к другому контуру

`syncExactModelControls` работает с `generation_provider` / `generation_model_id`
— это **модельный** каталог (Seedance, Veo), обычные наряды. Лимиты из отчёта
(3500 / 1000) оттуда же и верны.

Стратегический контур устроен иначе: движок живёт в `generation_intake_engine`,
маршруты приходят из `strategyProviderRoutes`, и там нет ни `promptLimit`, ни
`allowedResolutions`, ни `audioModes`. На маршруте стратегии профиль отключается
штатно — и это правильно.

Вывод: заявление «выбранная модель получает отдельный профиль формы» верно, но
**к трём стратегиям не относится**. На боевом платном маршруте выбранный
«Генератор 1/2/3» не влияет ни на разрешение, ни на звук, ни на финальный кадр,
ни на лимит инструкции.

Единственная реальная поломка здесь — **утечка профиля через «Повторить
настройки»**: `applyRepeatedSettings` / `applyModelIdentity` зовут
`syncExactModelControls` без проверки выбранной стратегии, а
`modelCanUseExistingLaunch` не смотрит на `disabled` самого селекта режима.
Секция разблокируется (`section.hidden = false`) на маршруте стратегии.
Подмена `brief.maxLength` при этом **не происходит** — внешний guard
`syncGenerationModeForm` (`app.js:27489`) возвращает 800 синхронно, в том же
стеке. То есть дефект косметический: ложная карточка «ПРОФИЛЬ ВЫБРАННОЙ МОДЕЛИ»
с чужим лимитом в подписи, плюс возвращённый в рабочее состояние селект «Звук».

### 2.2 «Каждая стратегия — отдельный модуль» — это один общий fieldset

`app.js:14128` — единственный на всю форму `<fieldset id="generation-strategy-assets">`;
модуль задаётся data-атрибутами на нём же. Переключение стратегии переиспользует
те же контролы и те же значения; `resetStrategyForm` вызывается только при
отсутствии выбранной строки.

Ветвление осталось двоичным «Копия / не Копия», а не тройным. Из-за этого модулю
«Аватар» подставляется текст, написанный для очереди из десяти роликов
(«Выберите ровно 1 исходных MP4 в нужном порядке… каждый исходник получит своё
ТЗ, цену и задачу») и включаются семь обязательных полей разбора механики.

Три из пяти объявленных состояний (`idle`, `editing`, `loading`) не имеют
визуального выражения — в слое есть правила только для `blocked` и `ready`.

### 2.3 Нумерация модулей нестабильна

`generation-strategy-view.js:847` считает номер по позиции в каталоге, а порядок
каталога — `avatarUgc → productSwap → rebuild`. Значит «Аватар» = МОДУЛЬ 01,
«Копия» = МОДУЛЬ 02. В интейке те же маршруты пронумерованы наоборот:
`copy_video` = 01, `avatar_video` = 02. Одна и та же стратегия называется и 01,
и 02 на двух экранах.

### 2.4 «Нет второго submit-маршрута» верно буквально, но проверка ничего не доказывает

Форма одна, это правда. Но платных диспетчеров два API и пять точек входа, и
одна из них — не submit вовсе: кнопка `retry-generation-strategy-start`
отправляет сохранённый платный запрос кликом, минуя
`syncGenerationStrategyFormReadiness` и повторную проверку состояния модуля.
Ассерт `source("app.js").count('<form id="mock-batch-form"') == 1` про это
ничего не говорит.

### 2.5 Мёртвые метки

`data-state="blocked"` у карточки стратегии никто не читает: селекторов
`.generation-strategy-card[data-state...]` в новом CSS ноль, потребителей в JS
нет. Хуже — тернарник ставит `selected` первым, поэтому уже выбранная и затем
отключённая сервером стратегия отрисуется как `selected`, а не `blocked`.

`profileState="blocked"` у профиля модели тоже ничего не выключает — только
меняет цвет рамки. Текст обещает «запуск заблокирован», кнопка при этом живая.

## 4. Видимые дефекты слоя

### 4.1 Чекбоксы и радиокнопки 18×42 — измерено, не выведено

Собран изолированный харнесс с тремя реальными стилями
(`styles.css` + `workspace-os-v4.css` + `workspace-ui-reference-v1.css`) на
`body.contentengine-desktop-v4`, снята геометрия в браузере:

```
checkbox: 18x42 · radio: 18x42 · min-height: 42px · width: 18px
```

Причина: `body.contentengine-desktop-v4 :is(input, select, textarea) { min-height: 42px }`
без исключения типов. Специфичность (0,1,2) перебивает
`styles.css:502` `input[type="checkbox"] { width: 18px; min-height: 18px }`
(0,1,1). `width` при этом не переопределяется — отсюда полоса 18×42.

Бьёт по всем юридически значимым подтверждениям: права на исходник, согласие на
внешность, чеклист рисков, подтверждение просмотра MP4. В репозитории уже есть
образец правильного исключения — `workspace-desks.css:352`
`:is(input:not([type="checkbox"]):not([type="radio"]), select, textarea)`.

### 4.2 Геометрические токены объявлены на `body`

`--ce-v4-top` и `--ce-v4-dock` заданы в блоке `body.contentengine-desktop-v4`,
а канонический shell объявляет их на `:root` — включая адаптивные
переопределения в `@media`. Кастомное свойство берётся с ближайшего предка,
объявившего его, поэтому `body` перекрывает `:root` независимо от медиазапроса.
Дыра: ширина 681–900px при высоте ≤760px — переопределение шелла мертво, а
собственный «низкий» блок слоя требует `min-width: 901px`.

### 4.3 Меню-бар накрывает контент

Бар сдвинут на `top: 8px`, но `height` остался `var(--ce-v4-top)`, а компенсация
отступа контента не увеличена. Фиксированный непрозрачный бар с `z-index: 440`
лежит поверх первых 8px прокручиваемого контента.

### 4.4 Вспомогательная кнопка покрашена как платный CTA

Правило `.generation-intake-v4__actions .btn:last-child` попало в одну группу с
`.btn-primary`. На экране «Создать видео по стратегии» единственная кнопка в
блоке действий — вспомогательная «Добавить исходники в проект». Слой делает её
золотой с тёмным текстом и весом 740, то есть визуально главным действием
экрана, хотя платная отправка живёт в форме ниже.

### 4.5 Контраст ниже собственного порога

`.ce-v4-desktop-project__meta` — 9px текстом цвета с контрастом 4.39:1 при
пороге репозитория 4.5. Строка «NN% готово / Открыть →» на карточке проекта.

Отдельно: градиентный заголовок панели результата ревью сделан через
`color: transparent` + `background-clip: text` без `@supports`, `forced-colors`
и `@media print` — в режиме высокой контрастности Windows и при печати заголовок
станет полностью невидимым.

## 5. Инвалидация платного контекста — что осталось незакрытым

Три места, где значение платного контекста меняется программно, без
`dispatchEvent`, и потому не проходит через `handleFormActivity`:

1. `applyExpressDefaults` пишет `generation_intake_engine` напрямую
   (`intake-v4.js:4143-4144`) — рядом, на `:2255-2260`, то же поле пишется
   правильно, с защитой и событиями.
2. `campaign_id` меняется программно в трёх новых местах; компенсирующий сброс
   чистит `checked`, но не `value` — во всех остальных точках инвалидации пара
   чистится вместе.
3. Чипы каскада `generation_intake_generator` / `_quality` / `_duration` не
   значатся в списке платного контекста `handleFormActivity`, хотя тот же diff
   добавил их в платный lock. Всё держится на компенсации из другого модуля,
   которая работает, только пока смонтирована компакт-панель «Копия».

Отдельно: `MutationObserver` панели «Копия» расширен на атрибуты, которые
пишутся безусловно при каждой синхронизации готовности, и не отключается на
время `mount`. Во время платного запуска поллер статусов раз в 5 с переписывает
атрибут → наблюдатель → `scheduleMount` → `mount` → бессобытийные записи выше.
Это ровно тот класс отказа, на котором панель «Копия» уже дважды вешала вкладку.

## 6. Порядок починки

1. **Закрыть «Создание» на сервере** — отказ до резервирования, а не 404 после.
2. **Научить `ready` знать про маршрут** и проверять все обязательные роли, а не
   только те, для которых нашёлся контрол.
3. **Починить релизный контракт**: привести версии в `index.html` к `build.json`.
4. **Исключить чекбоксы и радио из правила `min-height: 42px`.**
5. Провенанс: сделать метку «операторский текст» переживающей перерисовку и
   закрыть автозаполнение замысла без действия человека.
6. Перенести геометрические токены с `body` на `:root`, добавить слой в
   браузерные харнессы и в WCAG-проверку.
7. Убрать мёртвые метки либо довести их до реального эффекта.
8. Закрыть три бессобытийные записи платного контекста и защитить наблюдатель.
